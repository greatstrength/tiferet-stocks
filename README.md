# tiferet-stocks

## Watchlist storage

The reference configuration uses `data/watchlists.yml`; `.yaml`, `.yml` and `.json` files are supported through Tiferet's configuration repository. The starter YAML is empty. A missing file is an empty collection: reads return no watchlists and never create a file or directory, and the first save creates the file and any missing parent directories. Malformed files and access failures are not treated as empty.

Each watchlist is keyed by id under `watchlists`; its body contains its name, optional description and timestamps, and ordered `symbol_ids`. Only the watchlist repository writes storage. Reads leave bytes and timestamps unchanged. Saves preserve other watchlists and unrelated root nodes, but rewrite the whole file without locking; concurrent writers can lose changes, and YAML comments are not preserved. An unsupported extension is a core `ServiceError`, not a catalogued watchlist error.


## Watchlist features

The reference `stocks_client` session exposes `watchlists.get`, `watchlists.list`, `watchlists.create`, `watchlists.update`, `watchlists.delete`, `watchlists.add`, `watchlists.remove` and `watchlists.move`. Changes take `id`; create also takes `name`, optional `description` and initial `symbol_ids`. Update changes supplied name/description values. Symbol edits take `symbol_id`; add uses `index` and move uses `to_index`, defaulting to -1 (the end). Positions are zero-based; values past the end land last, and values below -1 are rejected.

Every successful change except delete stamps `updated_at`, setting `created_at` only on creation. An explicit offset-bearing ISO `at` overrides the event clock. Reads never stamp. Duplicate ids, absent watchlists/symbols and invalid negative positions are checked before aggregate mutation and resolve through the configured watchlist error catalog. Adding a ticker does not look it up. Changes work on private aggregates so rejected requests do not mutate service-held objects.

## Symbol aliases

Some tickers differ between the library and a provider: Yahoo expects `BRK-B` for the canonical `BRK.B`. The reference configuration reads provider ticker aliases from `data/symbols.yml`, an `aliases` list whose rows carry `provider` (`yahoo_chart`), `provider_ticker` and `canonical_id`. The symbol, quote and history features send the provider ticker and answer under the canonical ticker; providers stay alias-free. A missing symbols file adds no aliases and is never created. The Yahoo aliases that come out of the box (today `BRK.B` to `BRK-B`) ship as a Python asset, `YAHOO_DEFAULT_SYMBOL_ALIASES` in `tiferet_stocks/assets/symbol.py`; it is keyed by provider ticker, its data carries only `canonical_id`, the constant and its artifact section comments designate Yahoo, and the CLI seeds it into its bootstrap cache as an app constant injected into the symbol alias service, which hydrates the provider ticker and provider. An installed CLI therefore quotes `BRK.B` with no symbols file. Configured aliases take precedence: a `data/symbols.yml` row for the same provider ticker replaces the default, and the defaults are only the fallback. The programmatic `App` with the reference configuration does not build the stocks cache, so it reads the symbols file only.

## Command line

After `pip install .`, run `tiferet-stocks exchanges list` from any directory; no configuration file is needed. The stocks blueprint seeds its commands, features, services, sessions and errors into the bootstrap cache from packaged assets, the way core seeds its own CLI. A config.yml in the current directory, or one named with `--config`, is optional, and configured items take precedence over the packaged defaults: a `stocks_cli` session it declares is used, and services under `sessions.stocks_cli.services` replace the cached service of the same id (for example another price provider or watchlist path); without that session the cached one applies. Commands its CLI section lists follow the stocks commands. An explicit `--config` that does not exist is an error. The package installs code, not a writable configuration or data directory; the default watchlist and symbols paths are `data/watchlists.yml` and `data/symbols.yml`, CWD-relative. The reference config.yml in the repository keeps the sessions, services, features and errors for programmatic `App` use and has no `cli` section. The reference provider is Yahoo: `quotes get` fetches the whole list in one request to Yahoo's batch quote endpoint under an anonymous cookie and crumb session the provider keeps for reuse, and `quotes history` and symbol lookups use the chart endpoint one ticker at a time. A ticker Yahoo does not return is reported as a not_found failure row, never dropped. Quotes carry source `yahoo_quote`. The acceptance suite substitutes static prices/history and recorded Yahoo responses without network access.

The thirteen commands cover quotes get/history, symbols get/resolve, exchanges list, and watchlists list/get/create/update/delete/add/remove/move. Quote and lookup tables retain every warning and failure by symbol; other results use core's native formatting. `watchlists add ID SYMBOL` fails with WATCHLIST_NOT_FOUND for a missing watchlist unless `--create` is given, which creates it named by its id. Catalogued domain errors exit 1 and parser errors exit 2. See [CLI contract](docs/cli-contract.md) for syntax/configuration and [acceptance evidence](docs/cli-acceptance.md) for the twelve RFP criteria and installed-wheel tests.

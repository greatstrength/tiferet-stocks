# TSTK1-RFP-009 Symbol Alias Acceptance Packet

Scope: issue [#15](https://github.com/greatstrength/tiferet-stocks/issues/15), built on `v1.x-proto-build` from `v1.0.0b1`. No version bump, dependency change, alias-write event or CLI flag is included. These are local implementation checks for independent review, not QA approval or checked issue boxes.

## Decisions applied

`SymbolAlias` holds a provider id from `PROVIDERS` (initially `yahoo_chart`), a provider ticker and a canonical id. `SymbolAggregate.add_alias` enforces at most one alias per provider and only for that symbol; `apply_alias` is the only method that sets `id`. Rejections are uncatalogued model errors (`ALIAS_PROVIDER_EXISTS`, `ALIAS_NOT_FOR_SYMBOL`, `ALIAS_NOT_IN_COLLECTION`); when the alias events load configured aliases, they report an `ALIAS_PROVIDER_EXISTS` rejection as the catalogued error of the same id, with the canonical id, provider and both tickers. The outbound and inbound helpers are pure domain functions with exact ticker match. `SymbolAliasRepository` and `YahooChartSymbolRepository` live in `tiferet_stocks/repos/symbol.py` and are wired independently; both Yahoo repositories share `YahooChartClient` in `repos/yahoo.py`. `GetSymbol` raises `SYMBOL_NOT_FOUND` only when the provider reports its one ticker `not_found`; timeouts, HTTP errors, bad payloads and mismatches stay data. Quote symbols are canonicalized with `add_alias` and `apply_alias`; quotes, bars, warnings and failures are re-keyed by `symbol_id`.

## Boundaries

The seed file is not packaged in the wheel. The default path is the asset `DEFAULT_SYMBOL_CONFIG_FILE` in `tiferet_stocks/assets/symbol.py`, `data/symbols.yml`, CWD-relative, which `SymbolAliasRepository` uses when no `symbol_config` is given; the service registration carries no path, and a client application may pass `symbol_config` to its symbol alias service to read another file. (`tests/repos/test_symbol.py::test_alias_repo_defaults_to_asset_path`, `tests/test_symbol_alias_acceptance.py::test_alias_artifact_wired_independently`). The Yahoo default aliases (`YAHOO_DEFAULT_SYMBOL_ALIASES`) are a packaged asset the symbol, quote and history events reconcile with the configured aliases, so the programmatic App with the reference configuration and no local `data/symbols.yml` sends `BRK.B` as `BRK-B` (`test_missing_seed_uses_yahoo_defaults`), as does the installed CLI (`tests/test_cli_seed.py`). The later definition wins: a configured alias replaces a default with the same provider ticker or canonical id (`tests/events/test_symbol.py::test_alias_event_configured_alias_wins`), and the configured aliases are not resolved by order among themselves. A configured source holds at most one alias per provider for a canonical id: two rows for one provider and canonical id (two yahoo_chart rows for `BRK.B`) are a data-integrity error: the events run each configured row through `SymbolAggregate.add_alias` when they load the aliases, before any provider request, and report its rejection as the catalogued `ALIAS_PROVIDER_EXISTS`, which names the canonical id, the provider and both tickers (`Symbol BRK.B has more than one yahoo_chart alias: X1 and X2.`), so the CLI exits 1 with that message and no traceback, rather than one row being picked by order; the same canonical id under different providers is allowed (`tests/events/test_symbol.py::test_alias_event_rejects_two_configured_aliases_for_one_symbol`, `test_alias_event_allows_one_alias_per_provider_for_one_symbol`, `tests/events/test_quote.py::test_get_quotes_rejects_two_configured_aliases_for_one_symbol`, `tests/test_cli_seed.py::test_symbols_file_two_aliases_for_one_symbol_fail`, `test_installed_console_with_no_config`). Output reports canonical library ids only: a request for the provider ticker itself (`BRK-B`) is answered under the canonical `BRK.B`, because inbound re-keying follows the alias map, so `quotes get BRK.B BRK-B AAPL` reports `BRK.B` and `AAPL` and `BRK-B` falls away with no failure (`tests/events/test_quote.py::test_get_quotes_reports_canonical_library_ids_only`). The symbol events canonicalize the requested ids the same way: `symbols get BRK-B` answers as `BRK.B`, and `symbols resolve BRK.B BRK-B` reports `BRK.B` alone, with no symbol_mismatch row (`tests/events/test_symbol.py::test_resolve_symbols_reports_canonical_library_ids_only`, `tests/test_cli_seed.py::test_no_config_symbols_report_canonical_ids_only`). CLI rows render no alias column (`tests/test_cli_presentation.py::test_lookup_rows_omit_aliases`). `symbols get` for an unknown ticker now exits 1 through the CLI with `SYMBOL_NOT_FOUND`, replacing its 1.0.0b1 failure row. Events now inject `symbol_alias_service`, so a consumer configuration must declare that service before the symbol, quote and history events.

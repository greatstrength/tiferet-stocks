# TSTK1-RFP-009 Symbol Alias Acceptance Packet

Scope: issue [#15](https://github.com/greatstrength/tiferet-stocks/issues/15), built on `v1.x-proto-build` from `v1.0.0b1`. No version bump, dependency change, alias-write event or CLI flag is included. These are local implementation checks for independent review, not QA approval or checked issue boxes.

## Decisions applied

`SymbolAlias` holds a provider id from `PROVIDERS` (initially `yahoo_chart`), a provider ticker and a canonical id. `SymbolAggregate.set_alias` adds an alias only for that symbol and overwrites the symbol's alias for the same provider, so a symbol holds at most one alias per provider; `apply_alias` is the only method that sets `id`. Rejections are uncatalogued model errors (`ALIAS_NOT_FOR_SYMBOL`, `ALIAS_NOT_IN_COLLECTION`). The `SetSymbolAlias` domain event sets one alias on its symbol through `set_alias`, creating the symbol when it is new, and overwrites the symbol's alias for the same provider. It rejects a provider ticker already claimed by another symbol as the catalogued `ALIAS_TICKER_EXISTS`, which names the ticker, the provider and both symbols. The outbound and inbound helpers are pure domain functions with exact ticker match. `SymbolAliasRepository` and `YahooChartSymbolRepository` live in `tiferet_stocks/repos/symbol.py` and are wired independently; both Yahoo repositories share `YahooChartClient` in `repos/yahoo.py`. `GetSymbol` raises `SYMBOL_NOT_FOUND` only when the provider reports its one ticker `not_found`; timeouts, HTTP errors, bad payloads and mismatches stay data. Quote symbols are canonicalized with `set_alias` and `apply_alias`; quotes, bars, warnings and failures are re-keyed by `symbol_id`.

## Boundaries

The seed file is not packaged in the wheel. The default path is the asset `DEFAULT_SYMBOL_CONFIG_FILE` in `tiferet_stocks/assets/symbol.py`, `data/symbols.yml`, CWD-relative, which `SymbolAliasRepository` uses when no `symbol_config` is given; the service registration carries no path, and a client application may pass `symbol_config` to its symbol alias service to read another file. (`tests/repos/test_symbol.py::test_alias_repo_defaults_to_asset_path`, `tests/test_symbol_alias_acceptance.py::test_alias_artifact_wired_independently`). The Yahoo default aliases (`YAHOO_DEFAULT_SYMBOL_ALIASES`) are a packaged asset the symbol, quote and history events reconcile with the configured aliases, so the programmatic App with the reference configuration and no local `data/symbols.yml` sends `BRK.B` as `BRK-B` (`test_missing_seed_uses_yahoo_defaults`), as does the installed CLI (`tests/test_cli_seed.py`). The later definition wins: a configured alias replaces a default with the same provider ticker or canonical id (`tests/events/test_symbol.py::test_alias_event_configured_alias_wins`), and the events run each configured row through the `SetSymbolAlias` domain event, which adds the alias to its symbol or overwrites the symbol's alias for that provider, so of two rows for one provider and canonical id (`X1`, then `X2` for `BRK.B`) the later one wins; the same canonical id under different providers is allowed (`tests/events/test_symbol.py::test_set_symbol_alias_creates_the_symbol_alias`, `test_set_symbol_alias_overwrites_the_provider_alias`, `test_alias_event_later_configured_row_overwrites`, `test_alias_event_allows_one_alias_per_provider_for_one_symbol`, `tests/events/test_quote.py::test_get_quotes_later_configured_row_overwrites`, `tests/test_cli_seed.py::test_symbols_file_later_row_overwrites`). A configured source may not map one provider ticker to two symbols: when two symbols claim the same provider ticker (`BRK-B` for `BRK.B`, then for `BRKX`), `SetSymbolAlias` rejects the second row as a data-integrity error, the catalogued `ALIAS_TICKER_EXISTS`, which names the ticker, the provider and both symbols (`Ticker BRK-B is a yahoo_chart alias for more than one symbol: BRK.B and BRKX.`), so the CLI exits 1 with that message and no traceback, rather than one row being picked by order (`tests/events/test_symbol.py::test_set_symbol_alias_rejects_a_ticker_claimed_by_another_symbol`, `test_alias_event_rejects_a_ticker_claimed_by_two_symbols`, `tests/events/test_quote.py::test_get_quotes_rejects_a_ticker_claimed_by_two_symbols`, `tests/test_cli_seed.py::test_symbols_file_shared_ticker_fails`, `test_installed_console_with_no_config`). A configured alias still replaces a default with the same provider ticker or canonical id, and that shadowed default is dropped, so it does not raise a cross-symbol error (`tests/events/test_symbol.py::test_alias_event_configured_alias_wins`). Output reports canonical library ids only: a request for the provider ticker itself (`BRK-B`) is answered under the canonical `BRK.B`, because inbound re-keying follows the alias map, so `quotes get BRK.B BRK-B AAPL` reports `BRK.B` and `AAPL` and `BRK-B` falls away with no failure (`tests/events/test_quote.py::test_get_quotes_reports_canonical_library_ids_only`). The symbol events canonicalize the requested ids the same way: `symbols get BRK-B` answers as `BRK.B`, and `symbols resolve BRK.B BRK-B` reports `BRK.B` alone, with no symbol_mismatch row (`tests/events/test_symbol.py::test_resolve_symbols_reports_canonical_library_ids_only`, `tests/test_cli_seed.py::test_no_config_symbols_report_canonical_ids_only`). CLI rows render no alias column (`tests/test_cli_presentation.py::test_lookup_rows_omit_aliases`). `symbols get` for an unknown ticker now exits 1 through the CLI with `SYMBOL_NOT_FOUND`, replacing its 1.0.0b1 failure row. Events now inject `symbol_alias_service`, so a consumer configuration must declare that service before the symbol, quote and history events.

# TSTK1-RFP-005 CLI Command and Request Contract

Group 1 supplies the actual declarative catalog, command-id constants and request-binding parser factory. It does not yet install a console entrypoint or change response rendering; those are later conceptual commits. Existing programmatic feature signatures and results remain unchanged.

The parser delegates to released Tiferet's public parse_cli_args_handler. Its commands are the stocks commands seeded on the bootstrap cache under the ('stocks', 'cli', 'commands') prefix from `tiferet_stocks.assets.cli`, followed by any commands the app session's configured CLI service lists. No custom argparse implementation, invented dest field or private context assignment is used. Public parsing returns the same feature id and core headers, with a copied data dictionary adapting the names below.

| Command | Feature id | Parsed feature data |
|---|---|---|
| quotes get SYMBOLS+ | quotes.get | symbols list |
| quotes history SYMBOL --start DATE --end DATE | quotes.history | symbol, start, end; both date flags required |
| symbols get SYMBOL | symbols.get | public symbol becomes id |
| symbols resolve SYMBOLS+ [--expected-exchanges SYM=EXCHANGE ...] | symbols.resolve | public symbols becomes ids; expected_exchanges becomes exchanges |
| exchanges list | exchanges.list | no command-specific data |
| watchlists list | watchlists.list | no command-specific data |
| watchlists get ID | watchlists.get | id |
| watchlists create ID --name NAME [--description TEXT] [--symbol-ids SYMBOLS+] | watchlists.create | id, name, optional description and symbol_ids |
| watchlists update ID [--name NAME] [--description TEXT] | watchlists.update | id and optional supplied labels |
| watchlists delete ID | watchlists.delete | id |
| watchlists add ID SYMBOL [--index INDEX] [--create] | watchlists.add | id, symbol_id, integer index default -1, create bool default false |
| watchlists remove ID SYMBOL | watchlists.remove | id, symbol_id |
| watchlists move ID SYMBOL [--to-index INDEX] | watchlists.move | id, symbol_id, integer to_index default -1 |

Core list arguments use nargs '+' for one or more values. The optional exchange map uses core's dict interpretation of key=value tokens; omission preserves None for the existing event's optional exchanges argument. Negative -1/-2 values parse as integers; whether a value is a valid ordering request is decided by the existing watchlist feature, not duplicated in the parser. The command constants equal the already-existing feature ids.

## Validation

`tests/test_cli_catalog.py` checks the exact thirteen-command set, all argument signatures, name remapping, headers, unchanged parser inputs, scalar defaults, negative values and core parse failures. Integration cases dispatch all thirteen parsed commands through the existing App feature pipeline. Prices and daily bars use StaticPriceRepository; symbol lookups use recorded responses behind a patched urlopen and never call the network. Rejected -2 changes preserve stored bytes and retain the catalogued watchlist error code. `tests/test_cli_seed.py` checks the cache seed, asset and reference-config parity, the list-commands handler with and without configuration, the config-first session with the cached session as fallback, a config session service override, the Yahoo default aliases, an alias service that returns configured aliases only, and configured aliases replacing a default by provider ticker or by canonical id, and no-config runs in process and from the installed wheel.

## Symbol presentation

Quotes and lookup answers render as native core tables with one row per encountered symbol id, including ids represented only by warnings or failures. A quote answer is a QuoteList; rows walk its quotes list by symbol_id, so a ticker the provider omitted appears as a failed row with a not_found failure. Quote scalars remain scalars; quote_symbol_id and resolved_symbol_id retain provider identity independently of the requested symbol_id. Symbol metadata uses symbol_ prefixes, and quote fetched_at is retained when present. Rows report canonical library ids only: a symbol's aliases are not rendered, neither as a provider-ticker column nor as a nested cell. Numbered failure_N_* and warning_N_* columns preserve every field of every record, including repeated reasons, details and attempts; counts make omissions visible. Other responses keep core's native formatting. Presentation never replaces or modifies the library result.


## Running the installed CLI

Install the package and run `tiferet-stocks exchanges list`; no configuration file is required. The stocks `build_cache` mirrors core's admin build_cache: add_default_catalog for the stocks commands, services and sessions, plus add_default_features and add_default_errors, stacked over the standard `app.build_cache`, seeding the stocks commands, features, services, the stocks_cli and stocks_client sessions and the error catalog from packaged Python assets. No YAML is packaged. Symbols and aliases are domain concerns and stay out of the app session: no session, packaged or configured by the reference config.yml, carries a symbol or alias key, constant or service; the symbol alias service is registered with the services, its registration carries no path and the repository defaults to the `DEFAULT_SYMBOL_CONFIG_FILE` asset (`data/symbols.yml`); to read another file, a user sets `symbol_config` on a `symbol_alias_service` registration in the top-level `services` of config.yml, because session services are only for the app resolver container that builds the app session and `symbol_alias_service` is a plain service the domain events use; and the Yahoo default aliases come from the `a` assets inside the alias events, never the cache (`tests/test_cli_seed.py::test_symbols_stay_out_of_app_sessions`). A config.yml in the current working directory, or one named with `--config`, is optional. Configured items take precedence and the cache is the fallback. The stocks get_app_session calls core's get_app_session first without the cache, so a stocks_cli session the config declares is used. Services layer by id, the later definition winning: the cached services, then the config's top-level `services`, which `read_configured_services` reads through core's DIConfigRepository (each registration's unflagged dependency) and writes over the cached entries, then the session's `services`, which core's build_app_service_container applies last, so a session service beats a top-level service of the same id; only on APP_SESSION_NOT_FOUND, or FILE_NOT_FOUND for the optional default config.yml, does it call core's get_app_session with the cache. The list-commands handler loads the cached stocks commands, then whatever the session's CLI service lists in order, keyed by group key and key, which argparse sees, so the later definition wins and keeps the first position, as a core cache namespace keyed by id does; a configured command can replace a stocks command, two config entries for one group key and key (even under different YAML keys) resolve to the later one, and argparse never sees a conflicting subparser on any Python version. A missing default config.yml lists nothing extra. An explicit `--config` path that does not exist stays a FILE_NOT_FOUND fault. Core config readers all use the selected document; relative provider/watchlist paths retain CWD-relative core semantics.

`watchlists add ID SYMBOL` fails with the catalogued WATCHLIST_NOT_FOUND for a missing watchlist. With `--create`, a missing watchlist is created, named by its id, holding the one symbol; for an existing watchlist the flag changes nothing.

The stocks blueprint composes core's public get_app_session, build_app_service_container, build_service_resolver and compose_session_context factories. As core's tester CLI does, it also registers the app container with no flag so feature steps resolve the cached services without reading a DI configuration. The Yahoo default aliases follow core's multi-group asset catalog layout in `tiferet_stocks/assets/symbol.py`: the provider ticker id under `# *** constants (ids_yahoo)`, the alias data under `# *** constants (data_yahoo)` built by `create_default_symbol_alias_data(canonical_id)` in `tiferet_stocks/assets/core.py`, and `YAHOO_DEFAULT_SYMBOL_ALIASES`, keyed by provider ticker, under `# *** constants (groups)`; the data carries neither provider ticker nor provider. The constant is not seeded into the cache: the symbol alias service returns only the symbols-file rows, and the reconciliation happens at the domain event level, in `SymbolAliasEvent.get_aliases` (`tiferet_stocks/events/symbol.py`), the base event of `SymbolLookupEvent`, `GetQuotes` and `GetHistory`. It reads the defaults through the events' `a` assets import, hydrates each with its provider ticker and the yahoo_chart provider, and builds one merged map per call with the pure domain helper `merge_symbol_aliases`, which applies the later-definition rule: the defaults load first, then the configured aliases in file order; a default is dropped when a configured alias for the provider has its provider ticker or canonical id. Before the merge, the event runs every configured row through the `SetSymbolAlias` domain event, which adds the alias to its symbol or overwrites the symbol's alias for that provider, so a later row for the same symbol and provider wins; when two symbols claim the same provider ticker, `SetSymbolAlias` rejects the second row as the catalogued `ALIAS_TICKER_EXISTS`, naming the ticker, the provider and both symbols, so the CLI exits 1 with that message and no traceback, instead of resolving by order. A configured alias still replaces a default with the same provider ticker or canonical id, and that shadowed default is dropped, so it does not raise a cross-symbol error. The event uses that one map outbound and inbound, so with `BRK.B` configured as `BRKB.X` a raw `BRK-B` request stays `BRK-B`. It injects the request binder and stock response context, without changing core, shared domain features or private context slots. The real CliSessionContext prints responses, exits 1 for configured domain errors and uses argparse's exit 2 for command syntax errors. Missing/malformed configuration remains an infrastructure fault, not a new catalogued stocks error. `symbols get` for a ticker the provider does not know exits 1 with the catalogued SYMBOL_NOT_FOUND message; `symbols resolve` still reports such a ticker as a failure row.
